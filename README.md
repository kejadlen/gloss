# Arbitrary Definitions

A small design system — colour, type, space, elevation, motion, and eight
components — documented by a Jekyll site that renders every swatch, table, and
demo from the same YAML the stylesheet is compiled from.

**Site:** https://kejadlen.github.io/arbitrary-definitions-design-system/

## The idea

Almost every value in a design system is arbitrary. The base unit is 4px because
4 divides nicely; the accent is this orange because somebody liked it. What makes
it a *system* is not that the choices are correct but that they are written down
once, given names, actually used, and therefore changeable.

So this repository has exactly one source of truth — three YAML files under
`_data/tokens/` — and everything else is derived from it at build time:

- `assets/css/tokens.css` is generated by `_plugins/token_generator.rb`: a
  `:root` block, both dark-theme selectors, and a `prefers-reduced-motion`
  override that zeroes every duration token.
- The documentation tables and swatches loop over the same YAML through Liquid.
- Contrast ratios on the colour page are computed during the build by
  `lib/arbitrary_definitions/color_math.rb`, so a number on the page cannot
  disagree with the hex it describes.
- Component demos are rendered by a `{% example %}` Liquid block that outputs the
  live component and its highlighted source from one string, so the snippet can
  never drift from the demo.

No component stylesheet contains a colour literal or a duration — every one is a `var(--ad-*)`.

## Requirements

Ruby 4.0 (`.ruby-version` pins 4.0.6) and Bundler.

```console
$ bundle install
$ bundle exec rake          # tests, then build
$ bundle exec rake serve    # http://127.0.0.1:4000
```

## Tests

`test/` is plain Minitest against `lib/`, which has no Jekyll dependency. The
suite is the deploy gate in CI, and it asserts things that are easy to break by
accident:

- ten text pairings clear WCAG AA in **both** themes, and two non-text pairings
  clear 3:1;
- every ramp darkens monotonically from step to step;
- every semantic token resolves in both themes and documents its usage;
- no unresolved `ramp.step` reference reaches the generated CSS, and its braces
  balance.

```console
$ bundle exec rake test
23 runs, 199 assertions, 0 failures, 0 errors, 0 skips
```

Those assertions are not decorative. The accent started at `persimmon.600` and
the suite caught it at 4.17:1 against white — under the 4.5:1 floor — so it moved
to `persimmon.700`, and steps 500–800 of the ink ramp were darkened for the same
reason.

## Layout

| Path | What it is |
| --- | --- |
| `_data/tokens/` | Every value in the system: ramps, semantic aliases, scales. |
| `lib/arbitrary_definitions/` | Token compiler and WCAG colour maths. No Jekyll dependency. |
| `_plugins/` | Jekyll wiring: the generator, Liquid filters, the `example` block. |
| `_sass/` | Base, components, and the documentation site's own chrome. |
| `_foundations/`, `_components/`, `_patterns/` | The documentation collections. |
| `test/` | Minitest suite. |
| `.github/workflows/pages.yml` | Build on Ruby 4.0, test, deploy to Pages. |

## Deployment

GitHub's hosted Jekyll build cannot run this site — it ignores `_plugins/` and
pins its own Ruby — so `.github/workflows/pages.yml` builds it on Actions with
`ruby/setup-ruby` and uploads the result with `actions/deploy-pages`.

Every branch is built and tested; only the repository's default branch deploys.
Enable the target under **Settings → Pages → Build and deployment → Source:
GitHub Actions**.

## Using the CSS elsewhere

Two files, in this order, and no JavaScript:

```html
<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="style.css">
```

Retheming means overriding a dozen custom properties after `tokens.css` loads —
no recompile, no fork. See [Using the CSS](https://kejadlen.github.io/arbitrary-definitions-design-system/install/).
